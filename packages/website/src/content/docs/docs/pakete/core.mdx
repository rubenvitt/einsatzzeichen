Diese Seite richtet sich an Entwicklerinnen und Entwickler. Wer ein Zeichen nur finden,
herunterladen, drucken oder auf eine Karte legen möchte, braucht sie nicht — dafür gibt es
die [Anleitungen](/docs/anleitungen/).

`@einsatzzeichen/core` ist das Produkt: alles, was es braucht, um ein Zeichen zu bauen und
auszugeben. Wer die Bibliothek nutzt, braucht `core`, `schema` und einen Ausgabekanal. Der Weg
von der Beschreibung eines Zeichens zum fertigen Bild ist ein einziger Aufruf, `drawSymbol()`. Das
[Prüfpaket](/docs/pakete/conformance/) braucht dafür niemand; es hält die Belege, an denen sich
die Zeichen messen lassen.

Hier liegen die Bausteine: Grundzeichen, Organisationsfarben, Stärkeangaben, Kopfmarken,
Verwaltungsstufen, Funktionsfassungen, Fahrwerk, Körpermarken, Piktogramme, deutsche
Bezeichnungen, die drei Render-Themes, die dokumentierten Kontrastausnahmen und die Laufweiten der
Schrift Arimo. Bis Version 1.5 lagen sie im Paket `catalog`.

`core` ist zugleich der einzige Renderer des Projekts. Jeder Ausgabekanal — React, Web
Component, MapLibre, QGIS — geht durch `renderSvg` oder `renderCanvas`, damit aus derselben
Zeichnung überall dasselbe Bild entsteht. Wer selbst rastert, weicht ab; das ist der Grund für die
Regel.

Daneben sitzt hier der Kompositionsmotor: `compose()` setzt aus einer `SymbolSpec` und den
Bausteinen eine `Drawing` zusammen, `validateSpec()` prüft die Spec gegen die
Validierungsregeln, bevor gezeichnet wird. `drawSymbol()` ruft `compose()` mit der fertigen
Standardbelegung `DEFAULT_PORTS` auf und gibt dem Zeichen eine Beschreibung für Screenreader mit. Und die Gates: Kontrast, viewBox, A11y-Metadaten,
Textmetrik, Fingerprint-Vergleich gegen die Referenz.

`core` hat **null Fremdabhängigkeiten**, importiert kein `node:*` und hängt **nie** von
`conformance` ab — die Richtung geht immer `conformance → core → schema`.

## Kräftigere Striche in kleinen Bildern

Die Zeichen sind wie in der Vorlage mit Strichen von 0,5 mm gezeichnet. Wird ein Zeichen als
kleines Bild ausgegeben, etwa 16, 24 oder 32 Pixel breit, ist so ein Strich schmaler als ein
einzelner Bildpunkt. Der Bildschirm kann ihn dann nur als blassgraue Spur zeigen, nicht als klare
Linie. Das liegt nicht an der Zeichnung, sondern daran, dass ein Bild aus ganzen Bildpunkten
besteht.

Eine **Mindeststrichbreite** hebt solche Striche beim Zeichnen auf die Breite eines Bildpunkts an.
Die Zeichendaten ändern sich dabei nicht: sie bleiben so fein wie die Vorlage, nur das Bild in der
gewählten Größe wird kräftiger. In größeren Bildern sind die Striche ohnehin breit genug; dort
ändert sich nichts.

In `core` ist die Mindeststrichbreite standardmäßig **aus**. Ohne die Option erzeugen `renderSvg`
und `renderCanvas` byteweise dieselbe Ausgabe wie zuvor. Eingeschaltet wird sie mit einer Zahl:

```ts
import { RASTER_MIN_STROKE_WIDTH_PX, renderSvg } from '@einsatzzeichen/core';

// 1 px: der empfohlene Wert, für jede Größe derselbe
const svg = renderSvg(drawing, { size: 24, minStrokeWidthPx: RASTER_MIN_STROKE_WIDTH_PX });
```

| Punkt | Verhalten |
|---|---|
| Option | `minStrokeWidthPx` an `renderSvg` und `renderCanvas`, in Pixeln der Ausgabe |
| Vorgabe | aus (`undefined`) |
| Empfohlener Wert | `RASTER_MIN_STROKE_WIDTH_PX` = `1` |
| Voraussetzung | `size` muss gesetzt sein; sonst `RangeError`, weil ein frei skalierendes SVG keinen festen Pixelmaßstab hat |
| Ungültiger Wert | `0`, negativ oder nicht endlich: `RangeError` |
| Was angehoben wird | gestrichene Linien, die bei `size` schmaler als der Wert würden |
| Was bleibt | breitere Striche, Füllflächen, Text, Strichmuster; ein Strich der Breite 0 bleibt unsichtbar |
| `renderCanvas` | gemeint sind die Pixel der Leinwand, auf hochauflösenden Bildschirmen also Gerätepixel |

Was 1 px bei den üblichen 32 mm breiten Zeichen bedeutet:

| Ausgabebreite | 1 px entspricht | Wirkung auf 0,5-mm-Striche |
|---|---|---|
| 16 px | 2 mm | vierfach so breit |
| 24 px | 1,33 mm | knapp dreifach so breit |
| 32 px | 1 mm | doppelt so breit |
| 64 px | 0,5 mm | unverändert |
| ab 128 px | höchstens 0,25 mm | kein Zeichen des Katalogs ändert sich |

Mehr als 1 px ist nicht empfohlen: Die meisten Grundzeichen führen ihre Kontur 1 mm vom Rand. Bei
16 px reicht ein 1-px-Strich genau bis an den Rand, ein breiterer würde abgeschnitten, und enge
Innenzeichnungen liefen zu. Die Messwerte stehen in der Entscheidungsnotiz
[`docs/decisions/2026-09-29-lfh-584-mindeststrichbreite.md`](https://github.com/rubenvitt/einsatzzeichen/blob/main/docs/decisions/2026-09-29-lfh-584-mindeststrichbreite.md).

Das Kartenpaket [`maplibre`](/docs/pakete/maplibre/) schaltet die Mindeststrichbreite von sich aus
ein, weil Kartensymbole immer kleine Bilder sind. [React](/docs/pakete/react/) und die
[Web Component](/docs/pakete/web-component/) reichen sie nur durch.

## Aus der Grammatik speisen

Eine Oberfläche oder ein Skript, das Zeichen zusammensetzen lässt, braucht mehr als die Zeichnung:
welche Werte es gibt, welche gerade zur übrigen Beschreibung passen, warum eine Beschreibung nicht
trägt und woher ein Zeichen stammt. Das alles liefert `core` selbst — der
[Baukasten](/builder/) ist nur einer seiner Nutzer.

| Export | Was es tut |
|---|---|
| `SPEC_FIELD_VALUES`, `specFieldValues(field)` | der Wertevorrat je Feld: `one-of` und `list` mit ihren Werten, `flag`, `text` und `structured` nur gekennzeichnet |
| `vocabulary(spec, field, { candidates? })` | je Wert `allowed` (mit `derived: true`, wenn die Zeichnung abgeleitete Teile trägt) oder `blocked` — mit Grund `rule` (erklärte Regeln) oder `not-measured` (auch abgeleitet nicht zeichenbar, mit Reichweite) |
| `checkSpec(spec, options?)` | dieselbe Prüfung für eine ganze Beschreibung: die Zeichnung oder der erklärte Grund, statt eines Wurfs |
| `explainIssue(issue)`, `explainRejection(error)`, `RULE_EXPLANATIONS` | Titel, Erklärung und betroffenes Feld je Regel |
| `symbolProvenance(spec)` | `verbatim` (Körperhülle an einem Original belegt) oder `derived` |
| `serializeSpec`, `parseSpec`, `encodeSpecParam`, `decodeSpecParam`, `SpecParseError` | die kanonische Form als JSON und für Links; strenges Lesen mit Pfad im Fehler |

Geprüft wird immer über den echten Weg: `vocabulary()` und `checkSpec()` zeichnen jeden Kandidaten
mit `drawSymbol()`. Ein nacktes `validateSpec(spec)` reicht dafür nicht, weil erst die Komposition
den Kontext aus Funktionsfassung und Verwaltungskopf baut. Alle elf aufzählbaren Felder mit ihrem
vollen Vorrat (316 Werte) kosten zusammen wenige Millisekunden.

`kind` ist Pflicht, und daraus folgt die Reihenfolge: ein Skript beginnt bei `vocabulary({}, 'kind')`
und bekommt die Grundzeichenarten, die ohne weitere Angabe tragen. Jedes andere Feld verlangt eine
gesetzte Grundzeichenart. Bei Listen (`capabilities`, `bodyMarks`) fragt das Vokabular, ob sich ein
Wert **anhängen** lässt; der gesetzte Wert trägt `selected: true` und den Befund der Beschreibung,
wie sie ist.

```ts
import { checkSpec, decodeSpecParam, encodeSpecParam, symbolProvenance, vocabulary } from '@einsatzzeichen/core';
import type { SymbolSpec } from '@einsatzzeichen/schema';

// Welche Grundzeichenarten tragen ohne weitere Angabe?
const kinds = vocabulary({}, 'kind').filter((option) => option.status === 'allowed');
console.log(kinds.map((option) => option.value)); // ['formation', 'person', …]

// Welche technischen Füllungen passen zur THW-Formation — und warum nicht?
const spec: SymbolSpec = { kind: 'formation', organization: 'thw' };
for (const option of vocabulary(spec, 'technicalFill')) {
  if (option.status === 'blocked' && option.reason === 'rule') {
    console.log(option.value, option.issues[0]?.title); // Organisation und Füllung schließen sich aus
  }
}

const result = checkSpec({ ...spec, strength: 'gruppe' });
if (result.ok) {
  console.log(symbolProvenance({ ...spec, strength: 'gruppe' }).status); // 'verbatim' oder 'derived'
} else if (result.reason === 'rule') {
  for (const issue of result.issues) console.log(issue.field, issue.title, issue.explanation);
} else {
  console.log('nicht vermessen:', result.scope, result.message);
}

// Für einen Link: base64url über `{"v":1,"spec":{…}}`; beim Lesen streng, mit Pfad im Fehler.
const param = encodeSpecParam(spec);
console.log(decodeSpecParam(param)); // { kind: 'formation', organization: 'thw' }
```

## Freistehende Zeichen

Manche Zeichen stehen ohne Grundzeichen auf der Lagekarte: Pfeile für Bewegungen und Maßnahmen
(5.2), Linien und Grenzen (2.14 bis 2.20), das Wetter (5.8.7) und der Zustand eines Tieres
(5.8.6). Ein Pfeil folgt einem Verlauf, den man selbst legt; eine Grenze trennt Abschnitte; das
Wetter zeigt einen Wert allein oder die Wolke mit Regen, Hagel, Gewitter oder Schnee in einer von
vier Stärken; der Tierzustand bringt die Tierform gleich mit. Diese Zeichen beschreibt eine eigene
Art von Beschreibung neben der `SymbolSpec`, erkennbar am Feld `kind`.

| Export | Was es tut |
|---|---|
| `drawFreestanding(spec, options?)` | freistehendes Zeichen → `Drawing`, mit Beschreibung für Screenreader |
| `drawAnySpec(spec, options?)` | der gemeinsame Einstieg für beide Arten |
| `checkAnySpec(spec)` | die Zeichnung oder der erklärte Grund, statt eines Wurfs |
| `validateFreestandingSpec(spec)`, `FREESTANDING_RULE_IDS` | die Regeln der freistehenden Zeichen, mit Regel-ID; erklärt über `explainIssue()` |
| `FREESTANDING_FIELD_VALUES` | der Wertevorrat je Feld, je Art |
| `serializeAnySpec`, `parseAnySpec`, `encodeAnySpecParam`, `decodeAnySpecParam` | die kanonische Form für beide Arten; freistehende Zeichen stehen unter `freestanding` |
| `weatherDrawing`, `classifyWeather`, `WEATHER_CLOUD_PRECIPITATION`, `animalStateDrawing` | die Zeichenfunktionen und die Wetterregeln als Daten |

```ts
import { drawAnySpec, encodeAnySpecParam, renderSvg } from '@einsatzzeichen/core';
import type { AnySpec } from '@einsatzzeichen/schema';

// Schneefall unter der Wolke, mittlere Stärke
const schnee: AnySpec = { kind: 'weather', values: ['weather-cloudy', 'weather-snowing'], intensity: 'moderate' };
const zeichen: AnySpec[] = [
  // Gerichtete Bewegung, Verlauf in Millimetern auf 32 × 32 mm
  { kind: 'movement', movement: 'directed-movement', path: { points: [[2, 16], [30, 16]] } },
  // Grenze mit taktischer Stärke, auf 48 × 32 mm
  { kind: 'line', line: 'boundary-with-strength', path: { points: [[1, 16], [47, 16]] }, strength: 'zug' },
  schnee,
  { kind: 'animal-state', state: 'dead-animal' },
];
const svgs = zeichen.map((spec) => renderSvg(drawAnySpec(spec), { size: 64 }));
const link = encodeAnySpecParam(schnee); // base64url über {"v":1,"freestanding":{…}}
```

Die Grenzen dieser Zeichen sind Regeln mit eigener Kennung: eine Stärke gehört nur an die Grenze
mit taktischer Stärke, eine zweite Darstellung gibt es nur bei der Escape Route (Fluchtweg) und
beim kontaminierten Tier, ein Wetterzeichen trägt höchstens die Wolke und einen Niederschlag. Ein
Pfeil hängt nicht an einem Grundzeichen; die Vorlage zeigt das nur beim Transport einer Person,
und dort gehört der Pfeil zum Personenzustand. Ein Verlauf, der zu kurz ist oder über die
Zeichenfläche hinausragt, ist keine Regel, sondern ein gewöhnlicher Fehler der Zeichnung.

## Beispiel

Ein Zeichen beschreiben, zeichnen und als SVG ausgeben — ohne Prüfpaket. Die Spec ist E.1.1
„Bergungsgruppe" des THW: blaue Gruppe mit weißer Innenkontur, „B" im Körper, „THW" unten rechts.

```ts
import { CompositionError, REFERENCE_THEME, drawSymbol, renderSvg } from '@einsatzzeichen/core';
import type { SymbolSpec } from '@einsatzzeichen/schema';

const spec: SymbolSpec = {
  kind: 'formation',
  whiteInnerContour: true,
  organization: 'thw',
  strength: 'gruppe',
  labels: { center: 'B', bottomRight: 'THW' },
};

try {
  const drawing = drawSymbol(spec, { title: 'Bergungsgruppe' });
  const svg = renderSvg(drawing, { size: 64, idPrefix: 'ez-bergungsgruppe', theme: REFERENCE_THEME });
} catch (error) {
  // Verstößt die Spec gegen eine Regel, nennt die CompositionError jede Regel-ID einzeln.
  if (error instanceof CompositionError) console.error(error.issues.map((issue) => issue.rule));
  else throw error;
}
```

Ohne `title` bleibt das Zeichen ohne Titel; die Beschreibung leitet `drawSymbol()` immer selbst aus
der Spec ab, es sei denn, man gibt `description` oder `descriptionFromSpec` mit.

Wer einzelne Bausteine austauschen will, übergibt `compose()` eine abgewandelte Belegung.
`DEFAULT_PORTS` selbst ist eingefroren; die Änderung gilt nur für die eigene Kopie:

```ts
import { DEFAULT_PORTS, compose, describeSymbolSpec, type CatalogPorts } from '@einsatzzeichen/core';

// `spec` wie im Beispiel oben
const ports: CatalogPorts = {
  ...DEFAULT_PORTS,
  // Eigene Farbe für eine Organisation, alle anderen wie gehabt.
  organizationColor: (id) => (id === 'thw' ? 'schwarz' : DEFAULT_PORTS.organizationColor(id)),
};
const drawing = compose(spec, ports, { descriptionFromSpec: describeSymbolSpec });
```
