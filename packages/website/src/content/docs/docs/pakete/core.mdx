Diese Seite richtet sich an Entwicklerinnen und Entwickler. Wer ein Zeichen nur finden,
herunterladen, drucken oder auf eine Karte legen möchte, braucht sie nicht — dafür gibt es
die [Anleitungen](/docs/anleitungen/).

`@einsatzzeichen/core` ist das Produkt: alles, was es braucht, um ein Zeichen zu bauen und
auszugeben. Wer die Bibliothek nutzt, braucht `core`, `schema` und einen Ausgabekanal. Der Weg
von der Beschreibung eines Zeichens zum fertigen Bild ist ein einziger Aufruf, `drawSymbol()`. Das
[Prüfpaket](/docs/pakete/conformance/) braucht dafür niemand; es hält die Belege, an denen sich
die Zeichen messen lassen.

Hier liegen die Bausteine: Grundzeichen, Organisationsfarben, Stärkeangaben, Kopfmarken,
Verwaltungsstufen, Funktionsfassungen, Fahrwerk, Körpermarken, Piktogramme, deutsche
Bezeichnungen, die drei Render-Themes, die dokumentierten Kontrastausnahmen und die Laufweiten der
Schrift Arimo. Bis Version 1.5 lagen sie im Paket `catalog`.

`core` ist zugleich der einzige Renderer des Projekts. Jeder Ausgabekanal — React, Web
Component, MapLibre, QGIS — geht durch `renderSvg` oder `renderCanvas`, damit aus derselben
Zeichnung überall dasselbe Bild entsteht. Wer selbst rastert, weicht ab; das ist der Grund für die
Regel.

Daneben sitzt hier der Kompositionsmotor: `compose()` setzt aus einer `SymbolSpec` und den
Bausteinen eine `Drawing` zusammen, `validateSpec()` prüft die Spec gegen die
Validierungsregeln, bevor gezeichnet wird. `drawSymbol()` ruft `compose()` mit der fertigen
Standardbelegung `DEFAULT_PORTS` auf und gibt dem Zeichen eine Beschreibung für Screenreader mit. Und die Gates: Kontrast, viewBox, A11y-Metadaten,
Textmetrik, Fingerprint-Vergleich gegen die Referenz.

`core` hat **null Fremdabhängigkeiten**, importiert kein `node:*` und hängt **nie** von
`conformance` ab — die Richtung geht immer `conformance → core → schema`.

<span class="ez-note__title">Nicht veröffentlicht</span>

`private: true`, `main` zeigt auf `./src/index.ts`, kein Build-Schritt. Im Workspace:

```json
{ "dependencies": { "@einsatzzeichen/core": "workspace:*" } }
```

`core` und `schema` importieren kein `node:*` und laufen deshalb auch im Browser.

## Hauptexporte

| Export | Was es tut |
|---|---|
| `renderSvg(drawing, options)` | SVG als String; `options`: `size`, `idPrefix`, `theme` |
| `renderCanvas(drawing, ctx, options)` | dieselbe Zeichnung auf einen 2D-Kontext |
| `rasterDimensionsForWidth(viewBox, width)` | Rastermaße zu einer Zielbreite |
| `REFERENCE_THEME`, `colorFor`, `RenderTheme` | der Farbvertrag am Rendererrand |
| `drawSymbol(spec, options?)` | der Einstieg: `SymbolSpec` → `Drawing`, mit Standardbelegung und Beschreibung |
| `DEFAULT_PORTS` | die Standardbelegung der Bausteine (`CatalogPorts`), eingefroren |
| `compose(spec, ports, options)`, `CompositionError` | Komposition aus der `SymbolSpec` mit eigenen Bausteinen |
| `validateSpec(spec)`, `ValidationIssue`, `VALIDATION_RULE_IDS` | Regelprüfung mit Regel-ID je Befund |
| `matchFingerprint(...)` | Hüllenvergleich gegen die Referenz, Toleranz 0,01 SVG-Einheiten |
| `boundsOfMm`, `strokeBoundsOfMm` | Hüllenberechnung in Millimetern |
| `checkContrast`, `contrastRatio`, `relativeLuminance` | Kontrastgate |
| `checkViewBox`, `checkA11yMetadata`, `checkTextMetrics`, `checkClipping`, `checkPictogram` | die übrigen Gates |
| `profileFor(id)`, `placeHead(...)` | Layoutprofile und Kopfzonensetzung |
| `BASE_SYMBOLS`, `baseDrawing(kind)`, `innerField(...)` | die Grundzeichen und ihre Zeichnung |
| `ORGANIZATION_COLORS`, `organizationColor(id)` | Organisationsfarben |
| `strengthHead`, `technicalHeadMark`, `administrativeHead`, `functionRole` | die Kopfzonen |
| `vehicleChassis`, `bodyMark` | Fahrwerk und Körpermarken |
| `ALL_PICTOGRAMS`, `pictogram(...)`, `buildPictogramRegistry()` | die Piktogramme |
| `RENDER_THEMES`, `renderTheme(id)`, `isRenderThemeId(value)`, `ACCESSIBLE_LIGHT_THEME`, `PRINT_MONOCHROME_THEME` | die drei konkreten Themes |
| `CONTRAST_EXCEPTIONS`, `contrastExceptionFor(...)` | dokumentierte Kontrastausnahmen |
| `ARIMO_TEXT_METRICS` | Laufweiten der Schrift, ohne Schriftdatei |
| `describeSymbolSpec(spec)`, `ORGANIZATION_LABELS`, `STRENGTH_LABELS`, … | deutsche Bezeichnungen |

## Beispiel

Ein Zeichen beschreiben, zeichnen und als SVG ausgeben — ohne Prüfpaket. Die Spec ist E.1.1
„Bergungsgruppe" des THW: blaue Gruppe mit weißer Innenkontur, „B" im Körper, „THW" unten rechts.

```ts
import { CompositionError, REFERENCE_THEME, drawSymbol, renderSvg } from '@einsatzzeichen/core';
import type { SymbolSpec } from '@einsatzzeichen/schema';

const spec: SymbolSpec = {
  kind: 'formation',
  whiteInnerContour: true,
  organization: 'thw',
  strength: 'gruppe',
  labels: { center: 'B', bottomRight: 'THW' },
};

try {
  const drawing = drawSymbol(spec, { title: 'Bergungsgruppe' });
  const svg = renderSvg(drawing, { size: 64, idPrefix: 'ez-bergungsgruppe', theme: REFERENCE_THEME });
} catch (error) {
  // Verstößt die Spec gegen eine Regel, nennt die CompositionError jede Regel-ID einzeln.
  if (error instanceof CompositionError) console.error(error.issues.map((issue) => issue.rule));
  else throw error;
}
```

Ohne `title` bleibt das Zeichen ohne Titel; die Beschreibung leitet `drawSymbol()` immer selbst aus
der Spec ab, es sei denn, man gibt `description` oder `descriptionFromSpec` mit.

Wer einzelne Bausteine austauschen will, übergibt `compose()` eine abgewandelte Belegung.
`DEFAULT_PORTS` selbst ist eingefroren; die Änderung gilt nur für die eigene Kopie:

```ts
import { DEFAULT_PORTS, compose, describeSymbolSpec, type CatalogPorts } from '@einsatzzeichen/core';

// `spec` wie im Beispiel oben
const ports: CatalogPorts = {
  ...DEFAULT_PORTS,
  // Eigene Farbe für eine Organisation, alle anderen wie gehabt.
  organizationColor: (id) => (id === 'thw' ? 'schwarz' : DEFAULT_PORTS.organizationColor(id)),
};
const drawing = compose(spec, ports, { descriptionFromSpec: describeSymbolSpec });
```
