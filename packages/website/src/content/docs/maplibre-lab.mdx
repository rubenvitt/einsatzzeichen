Ein taktisches Zeichen auf einer Karte ist zweierlei: ein SVG im DOM, das man anklicken und mit
CSS anfassen kann, oder ein Bild im Kartenstil, das MapLibre selbst zeichnet und beim Zoomen und
Drehen mitführt. Diese Seite zeigt beides mit demselben Zeichen auf derselben Karte, damit der
Unterschied sichtbar wird und nicht behauptet werden muss.

Zur Auswahl stehen alle {symbols.length} Zeichen aus dem Katalog-Snapshot (Bezugsbestand
`{snapshot.baseline}`, gezeichnet von `@einsatzzeichen/core` {snapshot.coreVersion}). Die fünf
Punkte auf der Karte liegen um Bonn und bedeuten nichts — sie sind Platzhalter, keine Lage.

Ein `?symbol=<slug>` in der Adresse wählt das Zeichen vor; so verlinkt jede Symbolseite mit „Auf
der Karte ansehen" hierher. Gelesen wird der Parameter erst nach der Hydration, damit das
serverseitig gerenderte Markup mit dem ersten Client-Render übereinstimmt. Einen Wert, den die
Liste nicht kennt, meldet die Seite sichtbar, statt stillschweigend ein anderes Zeichen zu zeigen.

## Die zwei Wege

**Marker.** `renderSvg()` erzeugt das Markup, das Markup wird zum Inhalt eines `<div>`, und
`new maplibregl.Marker({ element })` hängt dieses `<div>` an eine Koordinate. Das Zeichen bleibt
ein DOM-Element: Vektorschärfe in jeder Zoomstufe, Ereignisse und Tooltips ohne Umweg. Dafür
kostet jeder Marker ein DOM-Element — bei ein paar hundert Zeichen wird das Scrollen zäh.

**Symbol Layer.** `addSymbolImage(map, id, drawing, { size, pixelRatio, theme })` aus
`@einsatzzeichen/maplibre` rastert die Zeichnung und meldet sie über `map.addImage()` im
Kartenstil an; eine `symbol`-Ebene zeigt sie über `icon-image` an jedem Punkt einer Quelle. Das
Zeichnen übernimmt dann MapLibre, auch bei vielen tausend Punkten. Dafür ist das Bild ein Raster:
Größe, Pixel Ratio und Farbprofil stehen beim Anlegen fest, und eine andere Einstellung ist ein
anderes Bild unter einer anderen ID.

```ts
import { addSymbolImage } from '@einsatzzeichen/maplibre';

addSymbolImage(map, 'ez:base.formation:64:2:reference', drawing, {
  size: 64,
  pixelRatio: 2,
});
map.addLayer({
  id: 'einsatzzeichen',
  type: 'symbol',
  source: 'lage',
  layout: { 'icon-image': 'ez:base.formation:64:2:reference', 'icon-overlap': 'always' },
});
```

`size × pixelRatio` muss eine ganze Zahl ergeben — der Bildpuffer kennt keine halben Pixel.
MapLibre rechnet über `pixelRatio` auf die CSS-Größe zurück; deshalb erscheint ein Zeichen bei
Pixel Ratio 1, 2 und 3 gleich groß, nur schärfer. Wenn die Größe zwischen Marker und Symbolebene
auseinanderläuft, ist die Rechnung falsch, nicht die Karte.

<div class="ez-note">
<span class="ez-note__title">Kartengrundlage</span>

Die Kacheln kommen von OpenFreeMap (Stil `positron`). OpenFreeMap nennt als Bedingung: „There are
no limits on the number of map views or requests. There's no registration, no user database, no
API keys, and no cookies“ — kommerzielle Nutzung ausdrücklich erlaubt, verpflichtend ist allein
die Namensnennung „OpenFreeMap © OpenMapTiles Data from OpenStreetMap“, die MapLibre unten rechts
in der Karte führt. Im Repository steht kein Schlüssel, weil keiner gebraucht wird. Wer ohne
fremden Dienst arbeiten will, setzt `basemap="none"`: dann zeigt die Karte nur eine
Hintergrundfläche und lädt nichts nach.

</div>

<div class="ez-note">
<span class="ez-note__title">Noch nicht gebaut</span>

**Clustering.** MapLibre kann Punkte zu Gruppen zusammenfassen (`cluster: true` an der
GeoJSON-Quelle); diese Seite tut es nicht, weil ein Cluster ein eigenes Zeichen bräuchte — welches
Zeichen für zehn verschiedene Einheiten steht, ist eine fachliche Frage und keine, die sich in
der Website beantworten lässt.

**Offline-Sprites.** Ein Sprite-Blatt mit allen Zeichen wäre der Weg für Karten ohne Netz; es zu
erzeugen ist Arbeit im Paket `@einsatzzeichen/maplibre` (Rasterung, Atlas, `sprite.json`), nicht
Arbeit der Website. Diese Seite baut deshalb einzelne Bilder zur Laufzeit statt ein Sprite
vorzutäuschen.

</div>
